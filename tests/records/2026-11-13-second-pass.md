# 2026-11-13 — Second review pass: claims nothing checked

Follow-up to `2026-11-13-external-review.md`. That pass found things that **ran and
lied** (a PASS printed after skipping half its checks, a corrupted path generated by a
substitution). This pass looked for a different family, and found it: **claims that no
mechanism checked at all** — spec clauses with no schema behind them, documentation
asserting behaviour the scripts did not have, a state directory asserting decisions it
never recorded.

Eleven defects. Two were introduced by the previous round's own fixes.

## State and content defects

### R1 — The example run asserted decisions it never recorded

`iterations/round-01.md` spoke of "`DEC` kind `stop`" and of a scale authorisation, and
`plan.md` said scale was "authorised by user at S0" — but `decisions/` was empty.

`CORE_SPEC.md` §4 lists `DEC` as a first-class entity, workflow 01 makes the scale
authorisation a gate, and workflow 06 makes the stop decision a `DEC`. The example
therefore violated three of its own requirements while presenting itself as a
conforming run. A reader auditing it would have found nothing to audit.

**Fix:** `DEC-001` (scale, with the actor decomposition justification) and `DEC-002`
(stop, with the rule that fired *and* the four that did not). The round record now
names both.

### R2 — The run stopped, and no report existed

`CORE_SPEC.md` §5: "`report.md` — written only when the run stops". The run stopped by
S5. There was no `report.md`.

**Fix:** written, per `templates/final-report.md`. Its first line states that no evidence
stage ran and every band is `weak`; the unresolved table is full; the dissent section
carries the Saxony-Anhalt seat's claim that no actor has both the means and the motive to
restart the project. A report that looks confident here would be the failure mode the
method exists to prevent, so the report is uncomfortable on purpose.

### R3 — Version drift, self-inflicted

After the 0.1.1 fix commit, `README.md` still announced `v0.1.0` while the generated
packages and `CHANGELOG` said 0.1.1.

**Fix:** bumped to 0.1.2 here, and the version now lives in one place
(`packaging/platforms.json`) with the README status line as the only manual copy. That
copy is exactly the thing that drifts, so it is now on the review checklist rather than
trusted.

### R3b — A stopped run with no recorded uncertainties

Found while fixing R1: the report listed open questions in prose and said "no `UNC`
entities were raised this run". Workflow 06 makes undecidable questions `UNC` entities,
and this run had three of them — whether the EUR 9.9bn was disbursed or only pledged,
Intel's exit cost at Magdeburg, and whether the aid approval lapsed on pause.

Being transparent about a gap is better than hiding it, but it is not the same as
closing it: the report could describe uncertainties no auditor could check. Three `UNC`
records now exist, each naming what it would take to resolve it and which hypothesis it
would move.

## Spec-versus-implementation drift

### R4 — A spec clause with no field behind it

`CORE_SPEC.md` §4 required that "`ACT.premises[]`, `HYP.premises[]` and `PRD.basis[]`"
resolve. `prediction.schema.json` has no `basis` property. The clause was unenforceable
by construction, and the validator could not have caught a violation because there was
nothing to violate.

**Fix:** the clause now covers premises only, with a stated reason — predictions inherit
their basis through their hypothesis, so a fact revision has exactly one place to be
corrected.

### R5 — An enforced hash with no documented algorithm

The `fact_snapshot` hash became real in 0.1.1 and the validator recomputes it. The
recipe was documented nowhere. Anyone regenerating a snapshot by a slightly different
convention — normalised whitespace, locale sort, hashing `FACT` files rather than
statements — would get a mismatch and conclude the validator was broken.

**Fix:** exact recipe in `CORE_SPEC.md` §5: `sha256` over `f"{id}\t{statement}"` joined
with newlines, `sorted()` in code-point order, verbatim statement, IDs taken from
`fact_snapshot.ids`.

### R6 — "Validated by cross-reference checks" was untrue

`CORE_SPEC.md` §4 said the seven prose-led entities are validated by cross-reference.
They were loaded by nothing: `collect()` iterated the eight schema directories only. A
`DEC` pointing at a hypothesis that does not exist was invisible.

**Fix:** the validator now loads `claims/`, `conflicts/`, `assumptions/`, `decisions/`,
`uncertainties/` as well, resolving their references. Verified by planting
`DEC-001` with `refs: ["HYP-999"]` — now an error. The spec wording was tightened to
match what actually happens: parsed, references resolved, no field-level schema.

### R7 — The anchor check that did not exist

`tests/workflow-tests.md` T4 asserted "No broken relative links … including README
anchors". `check_structure.py` skipped every target beginning with `#`. The claim was
false and untested.

**Fix:** anchors are now resolved against the file's own headings. Verified by planting
a link to a non-existent heading — now an error.

### R8 — A fixed vocabulary the example violated

§10 defines five bands. The example uses `weak, untested`. Either the example was wrong
or the vocabulary was too rigid; leaving both in place meant a reader could not tell
which one to follow.

**Fix:** the band must be one of the five, and may carry a qualifier drawn from the four
columns. The reason is recorded: `weak` covers both "evidence came out thin" and "no
evidence at all", and a reader deciding whether to act needs to distinguish them.

### R9 — A number in prose that goes stale

The A-vs-B record cited "118 checks" from the validator. That count changed twice
during these fixes. The number was evidence-shaped but not evidence.

**Fix:** replaced with a non-numeric assertion ("the state validator passes on the run").

### R10 — A required file that was not registered as required

`requirements.txt` was added in 0.1.1 but not added to `check_structure.py`'s `REQUIRED`
list, so deleting it would have passed the structure test.

**Fix:** registered.

## The pattern, stated plainly

Last round: mechanisms that ran and reported success they had not earned.
This round: assertions with no mechanism behind them at all.

Both are the same underlying failure — **a claim and a check that were never introduced
to each other**. In a repository whose argument is "the rules are enforced, not advised",
every unenforced claim is a hole in the argument, regardless of whether the claim happens
to be true.

Practical rule adopted: when adding a sentence that says something *is* checked, either
point at the line that checks it, or do not write the sentence.
